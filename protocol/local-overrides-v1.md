# Scoped local overrides v1

The optional CLI workflow loads an explicitly selected local UTF-8 file into
one expiring fulfillment rule in the existing disposable Experiment. It is a
response/JavaScript override, not a script evaluator, filesystem watcher or
baseline browser modification. Nothing is armed by preview or preparation.

## Browser-selected snapshot manager

The Interceptor UI also accepts one explicitly selected browser File. It bounds
its read to 64 KiB plus one detection byte, decodes exact UTF-8 and computes the
SHA-256 before displaying an inert preview. It does not obtain or invent an OS
path and cannot attest symlink or regular-file metadata. The filesystem checks
below apply to the CLI loader, not the browser-selected byte snapshot.

Reviewing and preparing sends nothing. Explicit Arm submits the same existing
`configure_request_interception` contract. Context changes, form edits and expiry
invalidate preparation; on-disk edits cannot alter the frozen snapshot. The UI
retains the attempted exact identity for guarded Disarm, including after an
unknown receipt. A public summary hides URL queries and is insufficient alone to
confirm an ambiguous arm. No automatic retry, request, execution, watcher,
persistence or provider upload occurs. Reload never rearms. Expiry is enforced
by the backend even if the UI closes.

## Prepare and operate

Use Node.js 22+. Create an Experiment with the existing API/UI, select its
primary disposable page, and select **target** action scope for that exact page.
Read its target ID and experiment ID from the local Experiment snapshot.

```sh
node tools/prepare-local-override.mjs --file ./reviewed.js
node tools/prepare-local-override.mjs --file ./reviewed.js \
  --url 'http://127.0.0.1:17777/fixture.js' \
  --target-id OWNED_TARGET --experiment-id 7 \
  --sha256 REVIEWED_SHA256 --content-type 'text/javascript; charset=utf-8' \
  --ttl-ms 60000 --output ./override-action.json
node tools/manage-local-override.mjs --arm ./override-action.json \
  --base-url http://127.0.0.1:17778
node tools/manage-local-override.mjs --disarm ./override-action.json \
  --base-url http://127.0.0.1:17778
```

The first command reports byte count and SHA-256 only. Review the actual file
locally, then explicitly supply its digest to prepare. Preparation fails if the
bytes changed. The prepared private action file contains the response body and
exact URL; keep it local and out of source control. Existing files are never
replaced. `--arm` is the explicit mutation step and sends only to the selected
numeric loopback backend (`127.0.0.1` or `[::1]`; no hostname resolution).
Its bounded, unencoded UTF-8 JSON receipt rejects duplicate keys and includes
target, experiment and expiry, without
response bytes. No target request is generated by these commands. A subsequent
request in that disposable target can execute replaced JavaScript as normal
browser content, so review replacement code before arming.

Arming is also available through the existing API:
`reb-api call debugger_action --base-url ORIGIN --body-file override-action.json`.
The API performs no filesystem access. If the operation is unconfirmed, inspect
the local Experiment before deciding whether to retry. The manager never retries,
follows redirects, attaches ambient credentials, consults environment proxy
settings, or uploads to a provider. A failed or interrupted receipt does not prove
the rule was disarmed: it may remain active until its original expiry. Inspect
the local Experiment and explicitly disarm the matching action if needed.

## Contract and lifecycle

`configure_request_interception` accepts optional `local_override` metadata:
version 1, exact canonical HTTP(S) URL, exact target ID, experiment ID,
`expires_at_ms` and the SHA-256 of `response_body`. These metadata are validated
with the ordinary fulfillment rule and appear in the public rule summary;
its URL query is omitted there. Full prepared action files remain sensitive.

- One rule slot, deterministic last successful explicit configuration wins.
  There is no rule-order ambiguity, wildcard local matching or merging.
- Only the selected primary disposable target can be armed. The target and
  experiment must still match. Changing action scope cannot broaden this rule:
  dispatch checks its fixed target, experiment, URL and method again.
- Only GET/HEAD and status 200 are supported initially. Transport pattern `*`
  pauses bounded disposable requests, then exact URL including query and method
  equality decides fulfillment. OPTIONS/preflight, other methods, other URLs,
  origins, targets and experiments bypass unchanged.
- Response metadata is limited to a supported UTF-8 type (plain text, JavaScript,
  JSON or CSS) and credential-free CORS. No cookies, redirects or auth headers.
- Expiry must be in the next five minutes; preparation defaults to one minute.
  Expiry is absolute from preparation, not renewed by arming. At dispatch, an
  expired or replaced rule bypasses unchanged, including queued requests.
  Existing interception audit records the bypass without file contents. The
  expiry and exact rule identity are rechecked after acquiring the CDP command
  writer, so waiting in its queue cannot silently extend permission. Once writing
  the command to the transport begins, it cannot be recalled; expiry/disarm is
  an admission gate, not a completion-time or in-flight cancellation guarantee.
- `--disarm` compares all six metadata fields plus method and content type against the currently armed
  local override before restoring continue mode. A changed rule (including URL, expiry, method or content type) conflicts and
  stays untouched. Disarm is allowed after expiry. Disposal/restart never rearms.
- This is a bounded file snapshot, not a live link. Later edits do not affect an
  armed snapshot. Prepare/review/arm again to apply new bytes. No file watching,
  broad directory reading, persistence, multiple-rule library or auto-arming.

Local files are at most 64 KiB, regular, valid exact UTF-8; symlink files and
parent directories, devices and pipes are refused. The loader checks metadata
before and after its bounded read. Its reviewed digest is rechecked by the
backend. The existing private no-overwrite writer is reused for prepared actions;
the Analyst library remains separate because it stores executable analysis
scripts with different semantics. Empty files are valid. Binary response bodies
and compressed assets are not supported. The local-only trust boundary is
unchanged; possession of an action file does not prove target authorization.

## Validation

`node tools/check-local-overrides.mjs` covers local files, digests, exact
preparation, expiry bounds, private publication, explicit arm/disarm against an
owned synthetic backend and unknown-outcome/no-retry behavior. Backend unit tests
cover scope, hash, headers, expiry and a deterministic queued-command admission
check. `make backend-e2e` exercises actual CDP fulfillment, exact owner rejection,
query/method/secondary-target bypass, guarded disarm conflicts and expiry on the
owned loopback fixture. No production credentials or third-party targets are used.
